# Tic Tac Toe (Flutter)

A premium black & gold Tic Tac Toe game — Material 3, animated marks and win
highlighting, full dark/light theme support, barrel-file organization, and
`provider`-based state management. Play locally with a friend (2-player) or
against an **unbeatable minimax AI** (vs-computer). Sign in with email/password
(or as a guest) via **Firebase Authentication**, and every completed match is
saved to your account's **Cloud Firestore** play history.

## Setup

```bash
flutter create --org com.example --project-name tic_tac_toe tic_tac_toe_app
```

Copy this project's `lib/` and `pubspec.yaml` into the generated project,
overwriting the defaults:

```bash
cp -r tic_tac_toe/lib/*        tic_tac_toe_app/lib/
cp    tic_tac_toe/pubspec.yaml tic_tac_toe_app/pubspec.yaml
```

Then, inside `tic_tac_toe_app`:

```bash
flutter pub get
flutter run
```

No API keys, no permissions, no location packages — this app is fully
self-contained and offline.

### If you hit the same `compileSdk` error as before

None of this project's core packages (`provider`, `shared_preferences`,
`google_fonts`) currently force a high `compileSdk`, so you likely won't hit
it. Firebase packages generally don't either, but if you do, open
`android/app/build.gradle.kts` and set:
```kotlin
compileSdk = 36
```
(hardcode the number — don't leave it as `flutter.compileSdkVersion`), then:
```bash
flutter clean
flutter pub get
flutter run
```

## Firebase setup (required before this runs)

This app **will not build/run correctly** until you connect it to a real
Firebase project — `lib/firebase_options.dart` currently ships with fake
placeholder values on purpose (so the code compiles for review), and needs
to be regenerated for your project.

**1. Create a Firebase project** at https://console.firebase.google.com
(free "Spark" plan is enough for development).

**2. Enable the two products this app uses**, inside your new project:
   - **Authentication** → Sign-in method → enable **Email/Password** and
     **Anonymous** (the "Continue as Guest" button uses anonymous auth).
   - **Firestore Database** → Create database → start in **production mode**
     (the included `firestore.rules` locks it down properly — see below).

**3. Install the FlutterFire CLI and connect your project:**
```bash
dart pub global activate flutterfire_cli
cd tic_tac_toe_app     # your actual project folder from step above
flutterfire configure
```
Follow the prompts: log into your Google account, select the Firebase
project you just created, and pick which platforms to configure (Android is
enough to get started; add iOS/Web later if needed). This **overwrites**
`lib/firebase_options.dart` with your project's real values — that's exactly
what you want.

**4. Deploy the included Firestore security rules** so users can only read
and write their own history:
```bash
npm install -g firebase-tools     # if you don't have the Firebase CLI yet
firebase login
firebase init firestore           # point it at firestore.rules in this repo
firebase deploy --only firestore:rules
```
(Or just paste the contents of `firestore.rules` into the Firestore Console
→ Rules tab → Publish, if you'd rather skip the CLI for this step.)

**5. Android-specific step**: `flutterfire configure` should handle this
automatically, but double-check `android/app/build.gradle.kts` has the
Google services plugin applied:
```kotlin
plugins {
    id("com.android.application")
    id("kotlin-android")
    id("com.google.gms.google-services")   // added by flutterfire configure
    id("dev.flutter.flutter-gradle-plugin")
}
```
and that `android/build.gradle.kts` (top-level) or `android/settings.gradle.kts`
declares the `com.google.gms.google-services` classpath/plugin version — again,
`flutterfire configure` does this for you.

**6. Run it:**
```bash
flutter pub get
flutter run
```

### How the auth + history pieces fit together

- **`AuthGate`** (`screens/auth/auth_gate.dart`) is the app's actual `home:`
  widget (see `main.dart`) — it watches `AuthProvider.status` and shows
  `LoginScreen` when signed out, `HomeScreen` when signed in, and a spinner
  while Firebase resolves the initial auth state.
- **`AuthProvider`** wraps `AuthService` (which wraps `FirebaseAuth`) and
  exposes `signIn`, `signUp`, `signInAnonymously`, and `signOut`, plus
  `isLoading`/`errorMessage` for the login/signup forms to react to.
- **`GameProvider.currentUid`** is kept in sync with the signed-in user by
  `AuthGate` on every rebuild. When a match ends, `GameProvider` fire-and-forgets
  a call to `HistoryService.saveMatch()` — if no one's signed in, this is
  skipped silently; if the save fails (e.g. offline), gameplay is never
  blocked or interrupted.
- **`HistoryScreen`** streams `HistoryService.watchHistory(uid)` — a live
  Firestore query — so new matches appear in the list in real time without
  needing to pull-to-refresh.
- **Firestore layout**: `users/{uid}/history/{autoId}`, each document holding
  `mode`, `result`, `humanPlayer`, and `playedAt` (see `MatchRecord.toMap()`
  in `models/match_record.dart`).

`widgets/widgets.dart`) that re-exports everything in that folder, so other
files only need **one import** instead of many:

## How the pieces fit together

- **State management**: `GameProvider` (board, turns, win detection, AI
  scheduling) and `ThemeProvider` (theme mode + persistence) are both plain
  `ChangeNotifier`s registered via `MultiProvider` in `main.dart`. Widgets
  read them with `context.watch<T>()` (rebuild on change) or
  `context.read<T>()` (fire-and-forget actions like `makeMove()`).
- **2-player mode**: `GameProvider.makeMove(index)` alternates `currentPlayer`
  between X and O after every valid move — no AI involved.
- **Vs-computer mode**: after the human's move, if it's now the computer's
  turn, `GameProvider` waits `AppConstants.aiMoveDelay` (550ms, so it doesn't
  feel instant/robotic) then calls `AiService.getBestMove()`, which runs
  minimax with alpha-beta-style pruning over all remaining empty cells. The
  AI never loses — best case for you is a draw.
- **Theming**: `AppColors` defines the black/gold palette once; `AppTheme`
  builds a `ThemeData` for light and dark using the *same* gold accents but
  different backgrounds (near-black vs. warm cream). Toggle via the sun/moon
  button in the app bar — preference is saved with `SharedPreferences` so it
  persists across restarts.
- **Win highlighting**: `AppConstants.winningLines` lists all 8 possible
  3-in-a-row index combinations. When a win is detected, `GameProvider`
  stores the matching line, and `GameBoard`/`GameCell` render those three
  cells with a gold glow.
